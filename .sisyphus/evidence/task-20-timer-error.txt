# Task 20 affine monotonic timers edge/error evidence

Date: 2026-08-21

## Contract edge coverage

- Generation exhaustion unchanged-state behavior is covered by `monotonic_timer_generation_exhaustion_preserves_armed_state` and `monotonic_timer_generation_exhaustion_preserves_disarmed_state`.
  - `arm` and `disarm` both preflight `generation.checked_add(1)`.
  - On `u64::MAX`, both return `MonotonicTimerError::GenerationExhausted { last_issued_generation: u64::MAX }`.
  - Armed timers retain the exact prior deadline and source generation; disarmed timers remain disarmed with no sentinel deadline.
- Disarmed deadline error is covered by `monotonic_timer_new_is_disarmed_with_stable_readiness_source`, `monotonic_timer_repeated_disarm_advances_generation`, and the stdlib facade test.
  - `deadline()` returns `Err(MonotonicTimerNotArmedError::NotArmed)` while disarmed.
- Equality expiration is covered by `monotonic_timer_equality_is_expiration`.
  - Arming to `clock.now()` immediately produces a current ready wake.
- Stale wake filtering is covered by `monotonic_timer_stale_ready_wake_does_not_expire_newer_deadline`.
  - A queued wake for an old generation validates as `SystemReadyWakeStatus::StaleGeneration` after rearm.
  - The stale wake does not mutate the timer and does not expire the newer deadline.
- Stable source identity is covered by runtime and facade tests.
  - `readiness_source()` clones preserve identity across new, arm, disarm, and rearm.
