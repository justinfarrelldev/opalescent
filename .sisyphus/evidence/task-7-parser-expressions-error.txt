## Using owner escape acceptance decision - 2026-08-15

Atlas loose-end resolution: no parser-level owner-escape rejection was added for `using` in Task 7. A direct textual escape heuristic would be unsound at parser time because escape depends on semantic binding identity, shadowing, aliasing, return/closure/dataflow shape, and the ownership/type rules planned for Task 13. Task 7 therefore preserves `Stmt::Using { binding, acquisition, body }` explicitly in the AST and keeps type checking/codegen semantics as explicit not-implemented errors, so Task 13 can enforce owner escape with symbol/type information instead of a lossy parser guess.
