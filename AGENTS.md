# Plans

Plans live in the `plans` folder on the top-level of the project. Follow plans exactly. While implementing a plan, create a checklist in the checklists folder (in `plans`) that is full of checklist bullet points that are kept UP-TO-DATE with the implementation status.

## Methodology

Always use test-driven development with red-green-refactor. Never, ever skip any phases of red-green-refactor. When implementing new language features, make new test-projects to ensure the features work (with minimal scopes for each).

## Language Goals

Read the full STDLIB.md file, README.md, language-spec and OPALESCENT_CRASH_COURSE.md files in their entirety before starting work.

## Commits

Use atomic commits. You are not allowed to modify or skip the pre-commit hook.

## Reviews

After all planned work has been implemented, you must do a thorough code review of the work you have done to ensure it fully implements what was specified in a maintainable, safe manner. This is not a toy project - spare no expense on maintainability and readability over the long-term. This includes with code written in Opalescent.
